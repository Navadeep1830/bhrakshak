# BhuRakshak v3 — AI Landslide Early Warning & Risk Intelligence (SIH26001)

**भूरक्षक — Earth Guardian.** 4-layer landslide early-warning for the North East Region:
**WHERE** (susceptibility hex grid) → **WHEN** (I-D rainfall thresholds + calibrated probability prior + hysteresis) → **WHO'S IN THE WAY** (exposure, response priority, road detours) → **COMMUNICATE** (alerts, SMS, push, IVR/siren policy in 8 NER languages).

One Next.js app contains both halves:

| Surface | What it is |
|---|---|
| **Website Command Center** (`/`) | Map (satellite/terrain/street), district drill-down Risk Explorer, Operations (alerts, report inbox, roads, Comms & SMS), Analytics (live engine telemetry), **Simulation** tab (manual condition injection), Field Report |
| **Field phone app — APK** (`/mobile`) | Real installable Android app (`apk/BhuRakshakField-v1.0.apk`): street map with hazard hexes + alternative safe routes (turn-by-turn), street view scan, offline crack-photo capture + auto-sync, notification + SMS inbox, manual location picker |
| **Field phone app — in browser** (Field App button, auto-opens on < 640 px) | Same app embedded in the website for big-screen demos |

Everything runs on **zero external API keys** — Esri/OpenTopoMap/OpenStreetMap tiles, local SQLite, in-process engines.

## The Android APK (real app, not a shortcut)

`apk/BhuRakshakField-v1.0.apk` — install it on any Android 7+ phone ("install unknown apps"
must be allowed; it is debug-signed, which is normal for hackathon builds):

1. Start the server on the command-center laptop: `npm run dev`
2. Connect the phone to the **same Wi-Fi / hotspot**, find the laptop's IP
   (`ipconfig` on Windows, `ip a` on Linux/Mac)
3. Open **BhuRakshak Field** on the phone → enter `http://<laptop-ip>:3000` → **Connect**

The app remembers the server and connects straight to it from then on. It registers
as a **real device** (visible in Operations → Comms & SMS on the website), receives
live alert fan-out (notifications + SMS inbox), plans routes, submits photo reports
and queues them offline — all against the live engine.

- The phone client loads the server's `/mobile` route — a standalone, login-free
  surface (device auth, not website accounts).
- Server down? The app shows a retry / change-server screen.
- Want to rebuild or modify it? `android/` holds the full client source
  (WebView shell, no dependencies) and `android/build.sh` rebuilds the APK with
  plain SDK tools (no Gradle). Keystore `android/keystore.jks` (pass `bhrakshak`)
  keeps signatures consistent — rotate it before any Play Store release.

## The Simulation tab (single control point)

Every other section reads live state. **Simulation is the only place conditions can be injected** — that is deliberate, so judges can verify nothing is hardcoded:

1. **Manual model input** — pick district/zone, set rainfall (1 h / 24 h / 72 h), soil saturation, seismic trigger.
   - **Run prediction** (dry-run, no writes): the exact production functions (`physicalProb`, `thresholdTier`, `fuseLevel`, `buildDrivers`) compute probability, fused level, tier breakdown and driver contributions. Type random numbers → the output changes every time.
   - **Push to live engine**: writes real observation rows → production engine pass → escalations, alerts, notifications, SMS fan-out. Every dashboard tab updates.
2. **Presets** — cloudburst / extreme monsoon / M 5.2 quake / dry spell.
3. **Historic scenario replay — Noney / Tupul 2022** — 72-hour antecedent rainfall rebuilt step-by-step through the live engine; the first L3+ warning and the evacuation window emerge on their own.
4. **Return to calm** — decay rainfall; zones stand down and all-clears fire.

## Field app demo flow

1. Install the APK (recommended — see above) or open **Field App** (phone view). Map shows hex hazard zones, roads, detours.
2. **Set your position manually** — the pin-edit button (tap the map) or the place button (jump to a district's worst zone). Position persists across re-opens.
3. **Plan alternative safe routes** — tap a destination or use *Shelters* → nearest relief camps. Three routes (fastest / safest / alternate bypass) with **turn-by-turn directions**, hazard warnings ("Caution — landslide risk zone ML-EKH-153 (L4) on the right"), blocked roads and ETAs.
4. **Street view** — ground-level panorama scan of any hazard zone with driver bars.
5. **Report** — take a crack photo (AI pre-screens it), or flip **Simulate offline** in Sync and capture offline → watch the queue auto-sync when back online.
6. **Alerts** — live notifications + SMS inbox (with delivery states).

## Architecture (all in this repo)

```
src/lib/
  risk-engine.ts   I-D thresholds, calibrated prior, hysteresis, drivers, i18n (8 languages)
  engine.ts        evaluateAllZones() — the production pass; logs every run to ModelRun
  simulate.ts      manual injection / decay / dry-run prediction (Simulation tab backend)
  roads.ts         per-road corridor hazard, ML blockage prediction, bypass synthesis
  app-route.ts     3-option routing + turn-by-turn step synthesis from live geometry
  notify.ts        notification + SMS fan-out (Twilio/BSNL slot-in point)
  vision.ts        VLM photo pre-screen (falls back to heuristic offline)
  seed-core.ts     idempotent seed (auto-runs via src/instrumentation.ts)
prisma/schema.prisma  SQLite schema (zones, risk cells, alerts, reports, SMS, devices…)
src/app/api/         25+ REST endpoints (auth, zones, kpis, analytics, simulate, app/*…)
```

## Honest notes (for Q&A)

- The SMS gateway is simulated (rows + delivery transitions); the fan-out code is the slot-in point for a real Twilio/BSNL provider.
- Vision pre-screen uses a server-side VLM when reachable; heuristic fallback otherwise.
- Terrain susceptibility uses deterministic terrain statistics per zone; the analytics registry shows only live-computed metrics.
