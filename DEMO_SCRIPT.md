## 0. Opening line (15 s)

> "BhuRakshak is a 4-layer landslide early-warning system for the North East: **where** slopes are
> susceptible, **when** rainfall pushes them over thresholds, **who** is in the way, and it **warns**

## 1. Command Center — the live picture (60 s)

- Point at the KPI strip: **621 zones, ~48 lakh people monitored, alerts live, SMS 24 h**.
- Map: hexagon color = live hazard level L0–L4; towers = escalation; red roads = ML-predicted
  blockage; dashed cyan = auto-suggested bypasses. Click a hexagon → **dossier**: the 8 risk drivers
  with percentages, 48 h rainfall, sensors, DC playbook (Sec 34 DM Act checklist).

## 2. THE PROOF — Simulation tab (2 min) ⭐

This is the anti-"hardcoded" segment:

1. **Manual model input** → pick any zone. Set rainfall 1 h = 8, 24 h = 30, soil 45%.
   Press **Run prediction** → L0/L1, low probability. *Show the formula trace.*
2. Now drag 1 h to 60, 24 h to 240, soil 92% → **Run prediction** again → **L4, ~99%**,
   both I-D gates shown breached, driver bars re-weighted.
   > Say: "Same code path the engine uses — change any number, the model moves."
3. **Push to live engine** → the result card shows zones injected, before→after (L1→L4),
   alerts fired, notifications, **SMS dispatched (1,700+)**.
4. Switch to **Operations → Comms & SMS**: the outbox is filling in real time, delivery states
   flipping sent→delivered. (Every row is generated by the fan-out engine — not scripted.)
5. Switch to **Analytics → Engine telemetry**: last recompute timestamp, levels now, engine
   passes 24 h, avg lead time — all recomputed per request. Model registry shows live metrics only.

## 3. Historic scenario replay — Noney / Tupul 2022 (60 s)

Back on **Simulation**, press **Play scenario**. The 72-hour antecedent rainfall rebuild runs
through the live engine step by step (T−72 h → T−0). The first L3+ warning appears on its own
— point at the **"first warning"** chip and the computed **evacuation window (X hours)**.
> Say: "This is how the system would have seen the 2022 Noney disaster coming — hours before the peak."

Press **Reset** afterwards to stand the district down.

## 4. Field phone app — the citizen side (90 s)

Open **Field App** (header button; on a real phone it opens full-screen).

1. **Manual location**: "Judges, I'm not in the North East right now — so I place myself there."
   Pin-edit button → tap the map (or place button → a district's worst zone). Position persists.
2. **Plan alternative safe routes**: route button → tap a destination (or *Shelters* → nearest
   relief camp). Three routes: fastest / **safest (RECOMMENDED)** / alternate bypass — each with
   **turn-by-turn directions**, "via NH-6 Shillong–Sohra", blocked-road warnings, and
   **landslide-risk zones flagged left/right with P(24h)%**.
3. **Street view** on a hazard mark: ground-level corridor scan + what's driving the risk.
4. **Offline crack photo**: Sync tab → flip **simulate offline** → Report → take/choose a photo →
   "saved to offline queue". Flip back online → **auto-sync** → AI pre-screens it
   (flagged, ~95%) → SMS dispatches to officials. Show the photo arriving in
   **Operations → Report inbox** (website) with the offline-sync badge.

## 5. Risk Explorer — drill-down & factor percentages (60 s)

## Q&A defence table

| Question | Answer |
|---|---|
| "Is the data hardcoded?" | No. Open Simulation → Run prediction with random numbers — the model recomputes. Every metric card in Analytics is recomputed per request; the engine logs each pass (ModelRun rows). |
| "What are the messages in Operations?" | Real alert fan-out: when the engine escalates a zone to L3+, every registered device in scope gets a notification + SMS (rendered from 8-language templates with the zone's live data). Delivery states transition like a real gateway. |
| "Where do the routes come from?" | A corridor-hazard engine over the live zone grid: 3 candidate corridors scored by cumulative ML hazard, then turn-by-turn steps synthesized from real geometry, named from the live road network. |
| "What if there's no internet?" | Field app caches state; crack photos queue on-device and sync when the network returns. (Bluetooth mesh is the planned next layer for no-network valleys.) |
| "Why is SMS simulated?" | The fan-out engine, templates, scoping and delivery states are real; the transport is a dry-run gateway that is the documented slot-in point for Twilio/BSNL credentials. |
| "How is this different from IMD alerts?" | We fuse zone-level susceptibility with rainfall intensity-duration thresholds and a calibrated probability prior, with anti-flapping hysteresis — village-level, not district-level, and per-road detours. |
| "Model accuracy?" | Transparent by design: the I-D thresholds and prior are auditable (shown in the prediction card); the registry reports live telemetry instead of offline AUCs. |
